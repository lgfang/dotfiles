* Adjust System Settings

- Mouse:
  + Turn on "Natural scrolling"
  + Enable "Secondary click"
- Keyboard
  + Adjust "Key repeat rate" and "Delay until repeat"
  + Dictation:
    - Languages: select both English and Chinese
    - Shortcut: set to press right command twice
- Mouse/trackpad tracking speed: adjust
- Function Keys: turn on "Use F1, F2, etc. keys as standard function keys"
- Language input methods: add additional input methods, say "Pinyin -
  Simplified"
- Menu Bar
  + "Automatically hide and show the menu bar": set to "Always"
    - To reveal it manually using keyboard, press =Control+F2=, which moves
      keyboard focus to the menu bar.
  + Menu Bar Controls:
    * "Sound": change to "Always Show"
    * "Bluetooth": tick
- Remote Login: toggle on/off as needed

* Setup GnuPG (GPG)

** macOS: Use the GUI pinentry

1. Install =pinentry-mac=:

   #+begin_src bash
     brew install pinentry-mac
   #+end_src

2. Configure =gpg-agent= to use =pinentry-mac= by adding the following to =~/.gnupg/gpg-agent.conf=:

   #+begin_src snippet :tangle ~/.gnupg/gpg-agent.conf :mkdirp yes
     pinentry-program /opt/homebrew/bin/pinentry-mac
   #+end_src

3. Restart =gpg-agent=:

   #+begin_src bash
     killall gpg-agent
   #+end_src

** macOS: Disable saving passphrases to Keychain

Do not select =Save in Keychain= in the =pinentry-mac= dialog. To disable
Keychain integration by default, run:
#+begin_src sh
  defaults write org.gpgtools.pinentry-mac DisableKeychain -bool YES
  defaults write org.gpgtools.common DisableKeychain -bool YES
#+end_src

** Cache passphrases for longer

Add the following settings to =~/.gnupg/gpg-agent.conf=:
#+begin_src snippet :tangle ~/.gnupg/gpg-agent.conf :mkdirp yes
  default-cache-ttl 28800
  max-cache-ttl 8640000
#+end_src

** kanopy-oidc

* Overnight battery drain

** Symptom

A fully charged MacBook is closed and left in a bag on Friday, then is dead by
Sunday. Seen on the new M5 MacBook Pro with macOS Tahoe 26.5.2 and 26.6.

** Root cause: Bluetooth HID reconnection

While asleep, macOS relentlessly tries to reconnect Bluetooth keyboards/mice
that are paired but currently unreachable. This produces around 190
dark-wakes/hour, draining the battery at roughly 1.85%/hour.

** Workaround (sleepwatcher + blueutil)

macOS has NO built-in setting for this. Desired behaviour:

| Situation                       | Bluetooth | Can wake with BT keyboard |
|---------------------------------+-----------+---------------------------|
| Plugged in (incl. clamshell)    | stays on  | yes                       |
| On battery, lid open            | stays on  | yes                       |
| On battery, lid closed (bagged) | off       | no, by design             |

*** Install third party tools

#+begin_src bash
  brew install blueutil sleepwatcher
#+end_src

*** Compose/tangle scripts

Both hooks apply the same rule, so it lives in one sourced file. Applying it on
wake as well as on sleep is what makes it robust: the sleep hook only fires on a
sleep /transition/, so unplugging a Mac that is already asleep would otherwise
leave Bluetooth on indefinitely. Re-evaluating on every wake, dark wakes
included, caps that exposure at one wake cycle.

- Shared policy
  #+begin_src sh :tangle ~/.bluetooth-policy.sh :tangle-mode o700
    #!/bin/sh
    # Bluetooth stays on unless we are on battery with the lid closed.
    BLUEUTIL=/opt/homebrew/bin/blueutil
    MARKER="$HOME/.bluetooth-off-by-sleepwatcher"

    on_battery() { /usr/bin/pmset -g ps | head -1 | grep -q "Battery Power"; }
    lid_closed()  { /usr/sbin/ioreg -r -k AppleClamshellState -d 4 | grep -q '"AppleClamshellState" = Yes'; }

    apply_bluetooth_policy() {
        if on_battery && lid_closed; then
            if [ "$($BLUEUTIL -p)" = "1" ]; then
                $BLUEUTIL -p 0
                touch "$MARKER"
            fi
        elif [ -f "$MARKER" ]; then
            $BLUEUTIL -p 1
            rm -f "$MARKER"
        fi
    }
  #+end_src

- On sleep
  #+begin_src sh :tangle ~/.sleep :tangle-mode o700
    #!/bin/sh
    . "$HOME/.bluetooth-policy.sh"

    # This hook fires about a second before macOS switches the reported power
    # source to battery, so poll briefly rather than trust the first reading.
    i=0
    while [ $i -lt 6 ] && ! on_battery; do
        sleep 0.5
        i=$((i + 1))
    done

    apply_bluetooth_policy
  #+end_src

- On wake up
  #+begin_src sh :tangle ~/.wakeup :tangle-mode o700
    #!/bin/sh
    . "$HOME/.bluetooth-policy.sh"

    apply_bluetooth_policy
  #+end_src

*** Activate

#+begin_src bash
  brew services start sleepwatcher
#+end_src

Notes:
- The first time a hook runs, macOS prompts to let sleepwatcher use Bluetooth.
  This MUST be allowed (System Settings > Privacy & Security > Bluetooth).
  Until it is, =blueutil= cannot even read the radio state from inside the hook:
  it falsely reports 0, and writes silently do nothing.
- A separate prompt asks to let sleepwatcher monitor all keystrokes. Deny it.
  That is only needed for sleepwatcher's idle-detection features, not for the
  =-s= and =-w= hooks used here.
- The marker file means Bluetooth is only re-enabled if the script disabled it,
  so a manual "Bluetooth off" is never overridden on wake.
- Absolute paths are required, sleepwatcher runs hooks with a minimal
  environment.
- Arriving at the desk and connecting the dock fully wakes the Mac (display
  hotplug), which fires =~/.wakeup= and restores Bluetooth. A bare power-only
  plug-in with the lid still shut only dark-wakes, which fires the hook too.
- Unplugging, or closing the lid on, an already-sleeping Mac fires no sleep
  event. The wake hook is what covers these: Bluetooth stays on until the next
  maintenance wake, at most ~15 minutes, and is then switched off.
- Both hooks are idempotent, so running either one by hand is a safe way to test
  the current decision:
  #+begin_src bash
    ~/.wakeup; blueutil -p
  #+end_src

** Diagnostics (reference only)

#+begin_src bash
  # both Battery + AC profiles (plain -g shows only the currently active source):
  pmset -g custom

  # wake history, bucket by hour and watch "Charge:N%" and "Using AC/BATT":
  pmset -g log | grep -iE "DarkWake|^Wake "

  # which processes scheduled wakes:
  pmset -g log | grep "Wake Requests"
#+end_src

To capture the Bluetooth side, persist its info-level logs for one night, then
inspect the window around the storm onset. Note ~/usr/bin/log~, since a bare
~log~ collides with a fish builtin:
#+begin_src bash
  sudo log config --subsystem com.apple.bluetooth --mode "level:debug,persist:info"
  # ... sleep on battery overnight with Bluetooth ON, then:
  /usr/bin/log show --start '<onset-20min>' --end '<onset+20min>' \
      --predicate 'subsystem == "com.apple.bluetooth"' --info --debug
  # restore when done:
  sudo log config --subsystem com.apple.bluetooth --mode "level:default,persist:default"
#+end_src

Beware: unified logs do not survive a reboot, so analyse the capture the same
day.
